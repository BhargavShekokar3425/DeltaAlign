# E14: component contribution audit

Audit date: 2026-10-03. Decision: continue a **bounded attribution study**, but hold algorithm-novelty and paper-drafting claims. E13 validates useful exact feature/cost maintenance; this review finds substantial overlap with existing structural representations, incremental propagation and assignment repair. The remaining opportunity is an alignment-specific composition and evaluation question, not an established new algorithm. This is a targeted review, not an exhaustive proof that no equivalent method exists.

## Source-backed comparison

Timing figures across different objectives/hardware are not comparable. Exact mathematical inference, floating-point arithmetic equivalence and bitwise equality are distinct guarantees.

The GNN papers have different features and numerical implementations. Their published speedups cannot be used as head-to-head baselines for DeltaAlign. A local implementation of their general affected-neighborhood principle must be labeled an **adaptation**, not a reproduction of those systems.

## What the repository actually implements

The current descriptor has 27 coordinates: log degree/neighbor-degree mean/std, a fixed 12-bin neighbor-degree histogram, and log mean of neighboring raw histograms. Old/new neighborhoods of edited endpoints cover first-layer updates. Only changed histograms propagate farther, plus adjacency-changed endpoints. Rows are compared exactly to report actual dirty features. The updater still scans whole neighborhoods within support; it does not implement a general undo/redo aggregation engine. See `src/descriptor_cache.py` and E07.

Initial per-coordinate standard deviations are frozen, with constant coordinates replaced by one. This permits local normalized-feature maintenance. If scales were refitted globally, unchanged raw features could yield changed normalized costs; current local invalidation would then be incomplete. Fixed normalization is a required objective contract, not evidence of novelty. See E04 and `src/normalization.py`.

`src/cost_cache.py` maintains normalized features and a dense squared-Euclidean matrix. With a source dirty set of size a and target dirty set of size b, it computes a*n + b*(n-a) disjoint entries. Unchanged blocks remain valid under the fixed-scale contract. Avoiding duplicate intersections and retaining costs are implementation choices; this audit does not establish them as novel. Assignment still runs globally using compiled SciPy. Floating-point equality to that full implementation is measured, not a theorem about recovering true correspondence.

E13: 30 independent paired seed bundles at 2K/5K, 120 exact snapshots. At 5K, feature medians improve 7.74–17.92× and costs 1.84–5.42×; total medians are 1.03× BA, 1.24× ER and 1.03× WS. Peak RSS increases by median factors 1.17/1.14/1.06. Median initial WS NC is 15.64%. These remain positive component outcomes regardless of novelty, small total effects or higher memory. No new empirical speed/quality result was generated during this audit.

## Contribution decision and hypotheses

**Established:** reproducible exact snapshot-objective maintenance with separate stage, setup, quality and RSS accounting in this implementation. **Not established:** a new descriptor, a new assignment solver, a new general propagation technique, better alignment accuracy, or independent CPU repair components.

The defensible next question is experimental: *how much does refined histogram propagation and actual dirty-row detection add beyond conservative dependency-local recomputation with the same features, normalization, persistent costs and solver?* Earlier full-versus-maintained comparisons do not isolate this. This is a missing attribution control, not an asserted literature gap. A component-focused manuscript warrants this bounded test; a novel-method manuscript is premature. If the refined policy adds no useful gain, retain the engineering result and reconsider scope rather than relabeling established techniques as new.

Preregister [E15 attribution](e15_protocol.md). Keep a separate fixed-job timing repetition task for near-one 5K totals; it cannot resolve algorithm novelty. Real topology, long streams and quality redesign follow only after this control and contribution decision. No 10K or parallel expansion yet.

## Unresolved source/compatibility work

- [IDAGEmb extension, publisher abstract](https://www.sciencedirect.com/science/article/pii/S0169023X26000558): describes dynamic-embedding-based incremental schema/instance alignment. Full text was not accessible here; exactness, cost caching and cross-graph matching details remain unresolved. It is a relevant lead, not evidence of equivalence or absence.
- ReFeX full algorithm/pruning details require accessible full text; the narrow representation claim above uses its indexed original abstract.
- DynaMAGNA++ journal online-extension wording, supplements and current baseline implementation compatibility remain unresolved in this audit. The temporal objective itself is verified from the author preprint.
- Incremental graphlet maintenance, relational incremental view maintenance, dynamic pairwise distance/kernel maintenance, and broader online matching literature need further systematic review before any “first” or “novel” claim.

The source registry records access scope and locators. Search snippets from surveys were used for discovery only; substantive claims above use original papers/preprints or are explicitly limited to the original abstract. No authors were contacted and no external messages were sent.

[E15](e15_findings.md) is complete: refined features beat conservative features in all 30 seed streams; sparse-update feature/cost medians show additional gains beyond conservative locality. BA 1% bare costs do not improve despite fewer computed entries. This answers the missing attribution control positively for features and sparse costs, but does not establish algorithm novelty. Small total differences remain; [E16](e16_protocol.md) now targets repeated fixed-job 5K timing rather than extrapolating these 1K component results.
