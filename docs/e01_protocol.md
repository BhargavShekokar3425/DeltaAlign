# E01 candidate-dependency detection protocol

Detection only: no local repair, parallelism, or incremental speedup claim. Use two_hop_hist and frozen initial normalization at n=1,000, BA attachment 3, and 1% target observation noise. Five original development seeds (0–4) and five additional holdout seeds (5–9) are identified separately. Holdout validation covers the same topology/noise, not generalization across graph families.

For each independent reset, use requested combined-edge fractions 0.01%, 0.1%, 1%, 5%. Test source-only, target-only, and both-graph batches. Split both-graph budgets with the odd edit assigned to source; a one-edit both batch is therefore a source-only duplicate and not independent evidence. Target-update RNG derives from the existing update seed. Candidate K is 1, 2, 5, 10, or 20; each list is top-K plus its old assignment edge. Stable target-ID ordering resolves ties without using truth.

Run full descriptor recomputation as an explicit reference oracle. Confirm actual changed descriptors lie within radius-2 pre/post union support. Cached dense costs update changed source rows and changed target columns exactly; compare against full cdist. Source-only candidate updates refresh changed source rows. Any changed target can enter any source's candidates, so refresh all source rankings in that case. Compare candidate lists exactly against full refresh, including old feasibility edges. This handles newly entering candidates but does not claim sublinear indexing or incremental descriptor implementation. Cost-matrix copies and dense rank scans are retained as diagnostic overhead.

Compare conservative radius-2 support seeds against exact changed-feature seeds (an oracle aided diagnostic). Propagate target seeds through the inverse old alignment and old/new reverse candidate indexes; add rows whose lists changed. Repeatedly include every candidate target's old owner. Verify all allowed targets belong to the old image of the final repair set. Measure recall, precision, RF, closure expansion, queue depth/edge work, refreshed cost entries/ranking rows, and timings. Keep zero-change recalls undefined. FullAlign remains dense exact assignment; candidate K limits the detector only. Detection recall versus dense full changes is empirical, not guaranteed by candidate maintenance correctness.

A core risk is closure percolation: even structurally unaffected rows have alternatives connecting ownership chains. Inspect low K versus recall and final RF before selecting a candidate-restricted repair pilot. Preserve development/holdout breakdowns and missed vertex IDs. Full descriptor oracle and diagnostic metrics are excluded from reported component timings; do not interpret their sum as update latency.

The implementation now sorts neighbor degree values before computing their statistics. This prevents adjacency iteration order from producing numerical changes in untouched descriptors. This numerical correction applies to all modes; previously saved experiments remain preserved as historical outputs. An exact graph-neighbor-order invariance regression check accompanies the change.
