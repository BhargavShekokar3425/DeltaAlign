# E05 shared-latent evolution versus observation edits

E04 corrected extreme stress costs but left every paired sparse result unchanged. Dense compact repair still missed the quality guide, and keep-old retained higher NC/S3 than the full descriptor optimum. This study separates update semantics before tuning another algorithm or claiming alignment-quality gains.

Use fresh seeds 25–29, 1K BA attachment-3 graphs, two_hop_hist, corrected unit-constant initial scale frozen across updates, and initial observation noise 1%/5%. Load the same frozen E02 policy; no parameter selection. Retain all seven E03 repair/reference methods. Each trial resets to its initial pair. Hidden correspondence generates/evaluates datasets only; descriptors, seeds, candidates, and solvers never receive it.

Shared latent: G is the latent graph, H its permuted observation with an initial fixed XOR edge-noise mask. Apply valid source edits and toggle their permuted observations in H. This preserves the exact noise mask; target insertion/deletion direction can reverse on noise-flipped edges. Independent balanced: use the same source batch and separately sampled valid target edits. Both protocols have exactly b effective edits in each graph. Set b=max(1, floor(requested_fraction*(m_G+m_H)/2 + 0.5)); log requested/realized combined fractions and all actual counts. Minimum total budget is two edits, so the smallest requested fraction can overshoot; pair protocols by realized budgets, not rounded labels alone.

Run requested fractions 0.01%, 0.1%, 1%, 5%. Noise settings reuse graph/permutation seed bundles; they are paired conditions, not independent seed replicates. Record initial and updated observation-mask sizes, their symmetric difference, latent edit counts where defined, source/target insertion/deletion counts, initial NC/S3, quality against truth/keep-old, FRA/objective against full, candidate/region loss, and actual corrected normalization. Assert mask persistence for shared evolution and validate cost/candidate refresh and restricted feasibility.

Retain original descriptive sparse guides (RF<=20%, FRA>=99%, mean NC/S3 loss<=0.5 percentage points, J gap<=1%) without treating them as scientific thresholds. More importantly, compare repair/full with keep-old: how often does either actually correct old errors, or introduce new errors, and how much objective gain does it recover? Report the five-seed distribution and maximum gaps. A high FRA can arise because nothing changes; report full changed mappings and zero-change counts.

No boundary/stability term, local feature optimization, repeated stream, or end-to-end speedup is added. Full feature/dense-cost oracles remain. Decide whether the research claim targets stated-objective maintenance, improved identity recovery, or a stability/quality tradeoff. If shared evolution changes the conclusions, specify that operating regime explicitly; if keep-old still dominates truth/structure, do not count high NC alone as a repair contribution. Include a candid paper-readiness assessment and next evidence gap.
